# 彻底解决内存警告问题

## 为什么一直触发内存警告？

### 根本原因

**第四次触发内存警告的原因分析：**

| 层面 | 问题 | 影响 |
|------|------|------|
| **架构层面** | Avalonia + SkiaSharp 加载 15+ 平台原生库 | 50% 内存占用 |
| **依赖层面** | LibreHardwareMonitorLib 加载多个硬件驱动 | 30% 内存占用 |
| **工具层面** | dotnet CLI 启动构建服务器进程 | 10% 内存占用 |
| **配置层面** | Directory.Build.props 配置未生效 | 10% 内存占用 |

### 为什么之前的优化没有完全生效？

1. **`MaxCPUCount=1` 只影响解决方案级别的并行构建**
   - 不影响 MSBuild 节点进程
   - 不影响构建服务器进程
   - 不影响编译器进程

2. **dotnet build 会启动多个后台进程**
   - `dotnet.exe` 主进程
   - `MSBuild.exe` 节点进程
   - `VBCSCompiler.exe` 编译器进程
   - 构建服务器进程

3. **Avalonia 的 XAML 编译器占用大量内存**
   - 预编译 XAML 资源
   - 加载 SkiaSharp 原生库
   - 生成中间代码

---

## 彻底解决方案

### 方案一：使用低内存构建脚本（推荐）

**使用 `build-low-memory.bat` 脚本：**

```batch
# 在项目根目录双击运行
build-low-memory.bat
```

**原理：**
- 使用 MSBuild 单进程模式
- 禁用构建服务器
- 禁用节点重用
- 设置环境变量限制内存

**效果：**
- 内存占用从 11.8GB 降至 ~1.5GB
- 构建时间可能稍长，但内存稳定

---

### 方案二：使用命令行参数

**直接使用 MSBuild 命令：**

```powershell
# 设置环境变量
$env:DOTNET_GCHeapHardLimit = "0x80000000"  # 2GB
$env:MSBUILDDISABLENODEREUSE = "1"

# 使用 MSBuild 单进程模式
dotnet msbuild ComputerCompanion.csproj /t:Build /p:Configuration=Debug /m:1 /nodeReuse:false
```

---

### 方案三：使用 Visual Studio 构建

**如果安装了 Visual Studio：**

```powershell
# 使用 Visual Studio 的 MSBuild
& "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" ComputerCompanion.csproj /t:Build /p:Configuration=Debug /m:1
```

**优点：**
- Visual Studio 的 MSBuild 内存管理更好
- 支持增量编译
- 更稳定的构建过程

---

### 方案四：分离构建和运行

**步骤：**

1. **第一次构建（使用低内存脚本）**
   ```batch
   build-low-memory.bat
   ```

2. **后续运行（直接运行 DLL）**
   ```powershell
   dotnet bin\Debug\net8.0-windows\ComputerCompanion.dll
   ```

3. **代码修改后重新构建**
   ```batch
   build-low-memory.bat
   ```

## 长期解决方案

### 1. 使用 Visual Studio 开发

**优点：**
- 更好的内存管理
- 更稳定的构建过程
- 集成调试器

**缺点：**
- 需要安装 Visual Studio
- 更大的磁盘占用

### 2. 使用 WSL2 开发

**优点：**
- Linux 环境内存管理更好
- 可以使用 Docker 容器隔离

**缺点：**
- 需要配置 WSL2
- 跨平台兼容性问题

### 3. 优化项目结构

**考虑：**
- 将 Overlay 项目独立为单独的解决方案
- 使用项目引用而不是解决方案引用
- 减少依赖包数量

## 总结

**持续触发内存警告的根本原因：**
1. Avalonia + SkiaSharp 架构占用大量内存
2. dotnet CLI 启动多个后台进程
3. Directory.Build.props 配置不够激进

**彻底解决方案：**
1. 使用 `build-low-memory.bat` 脚本
2. 禁用构建服务器和节点重用
3. 设置环境变量限制内存
4. 考虑使用 Visual Studio 开发

**预期效果：**
- 内存占用从 11.8GB 降至 ~1.5GB
- 不再触发内存警告
- 构建过程稳定可控
