## 1. 架构概述

### 1.1 设计目标

本架构旨在为电脑伴侣提供一个高度模块化、可扩展、安全可靠的 Windows 桌面应用框架，支持：

- **模块化服务**: 各功能以独立服务形式组织，便于测试与维护
- **双进程模型**: 主程序与悬浮窗分离，互不阻塞 UI
- **安全通信**: 基于 Named Pipe + HMAC 签名的 IPC 协议
- **可扩展监控**: 基于 LibreHardwareMonitor 的硬件监控，结合 ETW 真实游戏帧率追踪
- **个性化外观**: JSON 主题包驱动的皮肤系统
- **规则化建议**: 本地规则引擎提供温度/资源占用告警

### 1.2 平台与技术栈

| 项目 | 说明 |
|------|------|
| **目标平台** | 仅 Windows（10/11 x64） |
| **UI 框架** | Avalonia UI 11.2.0 |
| **运行时** | .NET 8.0 |
| **MVVM** | CommunityToolkit.Mvvm |
| **硬件监控** | LibreHardwareMonitorLib |
| **IPC** | Windows Named Pipes + Newtonsoft.Json |
| **帧率追踪** | ETW（DXGI Present Events） |

### 1.3 架构原则

| 原则 | 描述 |
|------|------|
| SOLID 原则 | 单一职责、开闭原则、里氏替换、接口隔离、依赖反转 |
| 高内聚低耦合 | 模块内部高内聚，模块之间低耦合 |
| 可测试性 | 所有核心功能支持单元测试 |
| 默认安全 | 最小权限原则，所有进程间通信均签名校验 |

### 2.2 双进程模型

电脑伴侣由两个进程组成，通过 IPC 协议通信：

```
┌────────────────────┐                  ┌────────────────────┐
│   主程序进程        │   Named Pipe     │   悬浮窗进程        │
│  (Main Window)    │  ◄──────────►   │  (Overlay Window) │
│                    │                  │                    │
│  - MainWindow UI   │  - 服务器模式    │  - 客户端模式       │
│  - HardwareMonitor │                  │  - OverlayWindow   │
│  - Settings        │                  │  - OverlayViewModel│
│  - SettingsService │                  │  - IPC Client      │
│  - IPC Server      │                  │                    │
│  - TrayIconService │                  │                    │
│  - InsightService  │                  │                    │
│  - FanControlSvc   │                  │                    │
│  - SkinService     │                  │                    │
└────────────────────┘                  └────────────────────┘
```

**启动流程**：

```
用户启动应用
    │
    ▼
解析命令行参数
    │
    ├── 有 --overlay 参数 ──→ 启动悬浮窗模式
    │                          │
    │                          ▼
    │                   初始化 OverlayWindow
    │                   连接 IPC 客户端
    │
    └── 无参数 ──→ 启动主程序模式
                           │
                           ▼
                   初始化 MainWindow
                   启动 IPC 服务器
                   初始化系统托盘
                   启动悬浮窗进程（如启用）
```

主程序以 `--overlay` 参数启动子进程时，子进程作为 IPC 客户端连接主程序的 Named Pipe 服务器，主程序通过 IPC 协议将设置变更、退出信号等发送到悬浮窗。

## 3. IPC 协议规范

### 3.1 概述

本协议定义电脑伴侣主程序与悬浮窗进程之间的跨进程通信规范，确保消息的完整性、安全性和可靠性。

- **传输层**: Windows Named Pipes
- **序列化**: JSON
- **编码**: UTF-8
- **协议版本**: 1.0

### 3.2 通信接口

**Pipe 名称**：`ComputerCompanion_IPC`

| 参数 | 值 | 说明 |
|------|-----|------|
| 方向 | 双向 | 支持读写 |
| 传输模式 | Byte | 字节流 |
| 最大实例数 | 1 | 单连接 |
| 超时时间 | 5000ms | 连接超时 |

### 3.3 消息格式

所有消息遵循统一格式：

```json
{
  "Type": "string",
  "Data": "string",
  "Timestamp": "number",
  "Signature": "string"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `Type` | string | 是 | 消息类型标识 |
| `Data` | string | 否 | 消息数据（JSON 序列化字符串） |
| `Timestamp` | number | 是 | UTC 时间戳（Ticks） |
| `Signature` | string | 是 | HMAC-SHA256 签名 |

**消息帧格式**：在管道中以帧为单位传输：

```
┌──────────┬─────────────────────────────┐
│ 4 bytes  │         N bytes            │
│ 长度前缀 │       消息内容(JSON)        │
└──────────┴─────────────────────────────┘
```

- **长度前缀**: 小端序 32 位整数
- **最大消息长度**: 65536 字节 (64KB)

### 3.4 消息类型

| 消息类型 | 发送方 | 描述 |
|---------|-------|------|
| `SessionKey` | Server | 发送会话密钥 |
| `SettingsChanged` | Main | 通知设置变更 |
| `ShowMainWindow` | Overlay | 请求显示主窗口 |
| `ExitApplication` | Main | 通知退出应用 |
| `OverlayReady` | Overlay | 通知悬浮窗就绪 |

各类型数据格式示例：

```json
// SettingsChanged
{"Type":"SettingsChanged","Data":"{\"OverlayShowFPS\":true,\"OverlayShowGpu\":true}","Timestamp":638475920000000000,"Signature":"hmac-signature"}

// ShowMainWindow
{"Type":"ShowMainWindow","Data":"","Timestamp":638475920000000000,"Signature":"hmac-signature"}

// ExitApplication
{"Type":"ExitApplication","Data":"","Timestamp":638475920000000000,"Signature":"hmac-signature"}

// OverlayReady
{"Type":"OverlayReady","Data":"Overlay started successfully","Timestamp":638475920000000000,"Signature":"hmac-signature"}
```

### 3.5 错误码

| 错误码 | 含义 | 处理建议 |
|--------|------|---------|
| 0 | 成功 | 正常处理 |
| -1 | 无效消息格式 | 检查消息结构 |
| -2 | 无效消息类型 | 验证 Type 字段 |
| -3 | 签名验证失败 | 拒绝处理消息 |
| -4 | 消息过长 | 拆分消息或检查数据大小 |
| -5 | 连接超时 | 重试连接 |
| -6 | 管道已关闭 | 重新建立连接 |
| -7 | 权限不足 | 检查运行权限 |

### 3.6 通信流程

**连接建立流程**：

```
Main Window (Server)          Overlay (Client)
         |                          |
         | 1. Start Server          |
         |<-------------------------|
         |                          |
         | 2. WaitForConnection     |
         |                          | 3. Connect
         |<-------------------------|
         |                          |
         | 4. Send SessionKey       |
         |------------------------->|
         |                          |
         | 5. Connected             |
         |<-------------------------|
         |                          |
         | 6. Message Exchange      |
         |<========================>|
```

- **消息发送流程**：构建消息 → 生成时间戳 → 计算签名 → 序列化为 JSON → 添加长度前缀 → 写入管道 → 刷新缓冲区
- **消息接收流程**：读取 4 字节长度前缀 → 验证长度范围 (1-65536) → 读取消息内容 → 反序列化为对象 → 验证签名 → 分发到处理程序

### 3.7 安全机制

**签名算法**：使用 HMAC-SHA256 对消息进行签名。

- 签名数据格式：`Type|Data|Timestamp`
- 计算：`Signature = Base64(HMAC-SHA256(SecretKey, "Type|Data|Timestamp"))`

**密钥管理**：

- **存储位置**: `%APPDATA%\ComputerCompanion\security.key`
- **密钥长度**: 256 位 (32 字节)
- **生成方式**: 首次运行时自动生成随机密钥

**会话密钥**：服务器在连接建立时生成，有效期 30 分钟，Base64 编码的 128 位随机数。

**安全检查**：

| 检查项 | 说明 |
|--------|------|
| 签名验证 | 所有消息必须通过签名验证 |
| 长度限制 | 拒绝超过 64KB 的消息 |
| 时间戳检查 | 拒绝过期消息（时间差 > 5 分钟） |
| 消息类型白名单 | 只接受预定义的消息类型 |

### 3.8 重连机制

- 客户端连接失败后自动重试，重试间隔 2000ms
- 连接超时 5000ms，超时后触发 `Disconnected` 事件并自动重连
- 使用 `CancellationToken` 控制异步操作取消

## 4. 模块说明

### 4.1 硬件监控服务 (HardwareMonitorService)

#### 4.1.1 职责

实时采集和管理系统硬件信息，包括：

- **CPU**: 使用率、温度、风扇转速
- **GPU**: 使用率、温度、风扇转速、显存使用、时钟频率
- **内存**: 已用内存、总内存
- **网络**: 上传速率、下载速率、网络延迟
- **磁盘**: 可用空间、总空间
- **电池**: 电量百分比、充电状态
- **FPS**: 实时帧率（含 ETW 真实游戏帧率，详见 §5）

### 4.3 进程间通信服务 (IpcService)

#### 4.3.1 职责

主程序和悬浮窗进程之间的通信，支持：

- **设置同步**: 主程序设置变更后同步到悬浮窗
- **窗口控制**: 控制主窗口显示/隐藏
- **应用退出**: 通知悬浮窗进程退出

#### 4.3.2 架构

```
┌─────────────────┐           Named Pipe           ┌─────────────────┐
│    主程序       │ ◄──────────────────────────────► │   悬浮窗进程     │
│  (Server Mode)  │                                 │  (Client Mode)   │
└─────────────────┘                                 └─────────────────┘
```

#### 4.3.3 核心组件

| 组件 | 职责 |
|------|------|
| `NamedPipeServerStream` | 服务器端管道 |
| `NamedPipeClientStream` | 客户端管道 |
| `CancellationTokenSource` | 异步操作取消 |
| `IpcMessage` / `SecureIpcMessage` | 消息数据结构 |

#### 4.3.4 公共方法

| 方法 | 说明 |
|------|------|
| `StartServerAsync()` | 启动 IPC 服务器 |
| `ConnectAsync()` | 连接到 IPC 服务器（带自动重连） |
| `SendMessageAsync(message)` | 发送 IPC 消息（含 HMAC 签名） |
| `Dispose()` | 释放资源 |

#### 4.3.5 事件

| 事件 | 说明 |
|------|------|
| `MessageReceived` | 接收到消息时触发 |
| `Connected` | 连接建立时触发 |
| `Disconnected` | 连接断开时触发 |

#### 4.3.6 错误处理

| 场景 | 处理 |
|------|------|
| 连接超时 | 记录日志，自动重试 |
| 连接断开 | 触发 Disconnected 事件，自动重连 |
| 消息格式错误 | 记录日志，丢弃消息 |
| 管道错误 | 记录日志，重启管道 |
| 消息长度 0 / >65536 | 忽略 / 跳过 |
| JSON 解析失败 | 记录日志，丢弃消息 |

### 4.5 GPU 风扇曲线控制服务 (FanControlService)

#### 4.5.1 职责

基于 LibreHardwareMonitor 提供 GPU 风扇控制：

## 5. ETW FPS 监控

### 5.1 概述

传统的 `MarkFrame()` 仅能在应用自身渲染时统计 FPS，无法反映**真实游戏帧率**。本服务通过 **ETW (Event Tracing for Windows)** 追踪 **DXGI Present Events**，捕获系统级帧呈现事件，从而获得全屏/窗口模式游戏的实际帧率。

### 5.2 工作原理

```
游戏进程 ──(DXGI Present)──> Windows 图形栈
                                │
                                ▼
                       ETW 实时会话 (DXGI Provider)
                                │
                                ▼
                  HardwareMonitorService 解析事件
                                │
                                ▼
                     计算 FPS / FrameTime / 1% Low
```

- 监听 `Microsoft-Windows-DXGI-SwapChain`（或 `DXGI` Provider）的 Present 事件
- 每个 Present 事件视为一次"帧提交"
- 在滑动窗口（默认 1s）内统计帧数 → FPS

### 5.3 权限要求

ETW 监听系统级事件需要 **管理员权限**。应用清单 (`app.manifest`) 已声明 `requireAdministrator`。

> 未以管理员权限运行时，ETW FPS 自动降级，回退到基于应用渲染的 `MarkFrame()` 统计（仅应用自身帧率）。

### 5.4 关键指标

| 指标 | 说明 |
|------|------|
| `Fps` | 当前帧率（每秒帧数） |
| `FrameTimeMs` | 单帧耗时（毫秒） |
| `Fps1PercentLow` | 1% Low（最低 1% 帧率，反映卡顿） |

### 5.5 接口（参考）

```csharp
public interface IEtwFpsMonitor : IDisposable
{
    bool IsActive { get; }
    bool RequiresElevatedPrivilege { get; }
    void Start();
    void Stop();
    event EventHandler<FpsUpdatedEventArgs> FpsUpdated;
}

public class FpsUpdatedEventArgs : EventArgs
{
    public float Fps { get; set; }
    public float FrameTimeMs { get; set; }
    public float Fps1PercentLow { get; set; }
    public int? Pid { get; set; }   // 当前焦点进程
}
```

### 5.6 异常处理

| 场景 | 处理 |
|------|------|
| 非管理员权限 | 跳过 ETW 启动，记录日志，回退到 MarkFrame |
| 会话启动失败 | 记录日志，禁用 ETW 监控 |
| 事件解析失败 | 跳过该事件，不影响后续事件处理 |

## 7. 安全架构

### 7.1 安全原则

| 原则 | 描述 |
|------|------|
| 最小权限 | 仅请求必要权限（IPC + 硬件监控 + ETW） |
| 默认安全 | 默认配置即安全，所有 IPC 消息签名 |
| 纵深防御 | 多层安全防护 |
| 隐私优先 | 数据最小化原则（不向云端上传任何用户数据） |

### 7.2 安全措施

| 层级 | 措施 |
|------|------|
| 进程间通信 | HMAC-SHA256 签名 + 时间戳校验 + 长度限制 |
| 本地存储 | 配置文件存于用户 AppData，无敏感凭据 |
| 权限 | 仅声明必要权限（管理员权限用于硬件监控与 ETW） |
| 审计 | 完整操作日志 |
