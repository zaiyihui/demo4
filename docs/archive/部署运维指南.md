> 本文档合并自原《部署安装指南》《实施指南》《MSBuild 内存优化指南》《VSCode 构建优化配置指南》《内存优化完整指南》《彻底解决内存警告问题》六篇文档，作为部署与运维的唯一权威参考。

## 1. 环境配置要求

### 1.1 平台定位（Windows-only）

**电脑伴侣是 Windows-only 应用**，不支持 Linux/macOS。原因如下：

- 项目目标框架为 `net8.0-windows`，输出类型为 `WinExe`，仅生成 `ComputerCompanion.exe`。
- 依赖 `LibreHardwareMonitorLib` 进行硬件监控，该库仅支持 Windows。
- 电池、注册表自启、Avalonia ANGLE 原生依赖等均依赖 Windows 平台 API。

跨平台构建/运行不在支持范围内，请勿在非 Windows 环境下尝试构建或部署。

### 1.2 开发环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 (1809+) / Windows 11 (推荐) |
| .NET SDK | .NET 8.0 SDK (8.0.421，由 `global.json` 固定) |
| IDE | Visual Studio 2022 / Rider / VS Code |
| 构建工具 | dotnet CLI、PowerShell |
| PowerShell 执行策略 | `RemoteSigned`（运行项目脚本前必须设置） |

### 1.3 运行环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10/11 (x64) |
| .NET Runtime | .NET 8.0 Desktop Runtime（框架依赖模式部署时需要；自包含发布可省） |
| 权限 | 普通用户可运行；硬件监控、开机自启等需要管理员权限 |
| 显卡 | 支持 DirectX 11 的图形卡（悬浮窗透明效果） |

### 1.4 硬件建议

- CPU: Intel i5-6500 或同等性能处理器
- 内存: 8GB RAM 或更高
- 软件: LibreHardwareMonitor（已随 NuGet 包引入，无需单独安装）

## 2. 开发环境搭建

### 2.1 设置 PowerShell 执行策略（前置）

项目内置多个 PowerShell 脚本（统一构建脚本、内存优化、清理构建等），运行前需将当前用户执行策略设为 `RemoteSigned`：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

> 验证：`Get-ExecutionPolicy -List` 中 `CurrentUser` 应为 `RemoteSigned`。

### 2.2 安装 .NET SDK

1. 下载 .NET 8.0 SDK：https://dotnet.microsoft.com/download/dotnet/8.0
2. 运行安装程序，勾选 "Desktop development" 工作负载。
3. 验证安装：

```bash
dotnet --version
# 输出示例: 8.0.421
```

> 项目根目录 `global.json` 已固定 SDK 版本为 `8.0.421`，`rollForward: latestMinor`，避免 SDK 版本冲突。

### 2.3 克隆项目

```bash
git clone <repository-url>
cd ComputerCompanion
```

### 2.4 安装依赖

```bash
dotnet restore
```

### 2.5 构建项目（单线程模式 /m:1）

由于 Avalonia + SkiaSharp + LiveCharts2 会加载大量原生库，多进程并行构建会触发严重内存警告。**必须使用单线程构建**，并禁用共享编译与节点重用：

```bash
# 推荐的单线程构建命令（关键）
dotnet build ComputerCompanion.csproj /m:1 /p:UseSharedCompilation=false /p:ServerNodeReuse=false
```

等价地，可指定配置：

```bash
# Debug 构建
dotnet build ComputerCompanion.csproj -c Debug /m:1 /p:UseSharedCompilation=false /p:ServerNodeReuse=false

# Release 构建
dotnet build ComputerCompanion.csproj -c Release /m:1 /p:UseSharedCompilation=false /p:ServerNodeReuse=false
```

> 说明：`/m:1` 强制 MSBuild 单进程；`/p:UseSharedCompilation=false` 禁用共享编译服务器；`/p:ServerNodeReuse=false` 禁用节点重用。这三项在 `Directory.Build.props` 中已设为默认属性，手动命令行参数用于确保万无一失。

### 2.6 运行项目（通过 EXE 启用 F5 调试）

构建成功后会在 `bin/Debug/net8.0-windows/win-x64/` 下生成 `ComputerCompanion.exe`。**程序必须通过编译后的 EXE 运行**（而非直接 `dotnet ComputerCompanion.dll`），以正确启用 F5 调试与原生依赖加载：

```bash
# 直接运行编译后的 EXE
.\bin\Debug\net8.0-windows\win-x64\ComputerCompanion.exe

# 悬浮窗模式
.\bin\Debug\net8.0-windows\win-x64\ComputerCompanion.exe --overlay
```

VS Code 调试时，`launch.json` 的 `program` 应指向编译产物；如需 F5 调试，建议指向 `ComputerCompanion.exe`（或对应 `dll` 并通过 coreclr 附加），同时配置 "No Build" 与 "With Build" 两个配置以便按需构建：

- **首次/代码变更后**：使用 "With Build" 配置（`preLaunchTask: build`），先构建再启动。
- **后续运行**：使用 "No Build" 配置，直接启动已编译的 EXE，F5 启动时间从 35 分钟级降至数秒。

`tasks.json` 中的构建任务应加入内存限制环境变量：

```json
"options": {
    "env": {
        "DOTNET_GCHeapHardLimit": "0x80000000",
        "MSBUILDDISABLENODEREUSE": "1"
    }
}
```

## 3. 内存优化配置

构建过程中内存占用过高（曾出现 8~12GB）会导致频繁触发内存警告。项目已通过以下配置将 GC 堆硬限制设为 **2GB**（2147483648 字节），构建内存可降至 ~1.5GB。

### 3.1 根因分析

| 原因 | 占比 | 说明 |
|------|------|------|
| Avalonia + SkiaSharp | ~40-50% | 加载 15+ 平台原生库、XAML 编译 |
| LibreHardwareMonitorLib | ~30% | 加载多个硬件驱动 |
| MSBuild 多进程节点 | ~20% | 每个项目单独进程、节点重用 |
| 缺少内存限制 | ~10% | GC 不主动释放 |

`MaxCPUCount=1` 只影响解决方案级并行构建，不影响 MSBuild 节点进程、构建服务器、编译器进程，因此还需配合 `UseSharedCompilation=false`、`NodeReuse=false` 及 GC 堆硬限制。

### 3.2 Directory.Build.props（构建期限制）

项目根目录 `Directory.Build.props` 关键配置：

```xml
<PropertyGroup>
  <!-- 强制单进程构建 -->
  <MaxCPUCount>1</MaxCPUCount>
  <BuildInParallel>false</BuildInParallel>
  <UseSharedCompilation>false</UseSharedCompilation>
  <NodeReuse>false</NodeReuse>

  <!-- GC 堆硬限制：2GB (0x80000000 = 2147483648 bytes) -->
  <GCHeapHardLimit>0x80000000</GCHeapHardLimit>
  <GCHeapHardLimitPercent>50</GCHeapHardLimitPercent>
  <GCHeapCompaction>true</GCHeapCompaction>
  <GCServer>false</GCServer>

  <!-- 禁用所有构建服务器 -->
  <UseRazorBuildServer>false</UseRazorBuildServer>
  <UseRoslynBuildServer>false</UseRoslynBuildServer>
  <UseVBCSCompilerServer>false</UseVBCSCompilerServer>
</PropertyGroup>
```

### 3.3 runtimeconfig.template.json（运行期限制）

项目根目录 `runtimeconfig.template.json`，限制 .NET 运行时最大内存为 **2GB**：

```json
{
  "runtimeOptions": {
    "configProperties": {
      "System.GC.Server": false,
      "System.GC.Concurrent": true,
      "System.GC.HeapHardLimit": 2147483648,
      "System.GC.HeapHardLimitPercent": 50,
      "System.GC.RetainVM": false,
      "System.GC.HeapCompactionMode": 1,
      "System.Threading.ThreadPool.MinThreads": 2,
      "System.Threading.ThreadPool.MaxThreads": 8
    }
  }
}
```

> `2147483648` = 2 × 1024 × 1024 × 1024 = **2GB**，与 `Directory.Build.props` 的 `GCHeapHardLimit=0x80000000` 一致。

### 3.4 .env.build（构建环境变量）

```ini
DOTNET_GCHeapHardLimit=0x80000000
DOTNET_gcServer=0
MSBUILDDISABLENODEREUSE=1
DOTNET_CLI_TELEMETRY_OPTOUT=1
DOTNET_SKIP_FIRST_TIME_EXPERIENCE=1
UseSharedCompilation=false
```

### 3.5 内存监控与优化效果

| 指标 | 优化前 | 优化后 | 改善 |
|------|--------|--------|------|
| 构建内存 | 8~12 GB | ~1.5 GB | -80% ~ -87% |
| 运行内存 | ~2 GB | ~1.2 GB | -40% |
| 系统内存使用率 | 96% | ~70% | -26% |
| 增量构建时间 | 35 分钟 | 1-2 分钟 | -94% |

长期监控建议：

- 警告阈值：系统内存 > 80%；严重 > 90%；紧急 > 95%。
- 实时监控：`dotnet-counters monitor --process-id <PID>`。
- 内存分析：`dotnet-trace collect --process-id <PID>`。

## 4. 构建与运行脚本

### 4.1 统一构建脚本 `构建脚本.ps1`

项目根目录的 `构建脚本.ps1` 是统一入口，封装了内存优化、单线程构建等参数，支持 Build / Run / Publish / Clean 四个动作：

```powershell
# 构建（Debug，默认先清理）
.\构建脚本.ps1 -Action Build -Configuration Debug

# 运行（无输出时自动构建）
.\构建脚本.ps1 -Action Run -Configuration Debug

# 发布（Release，单文件自包含）
.\构建脚本.ps1 -Action Publish -Configuration Release

# 清理
.\构建脚本.ps1 -Action Clean
```

脚本内部关键行为：
- `Set-MemoryOptimization` 设置 `DOTNET_GCHeapHardLimit=2147483648`（2GB）、`MSBUILDDISABLENODEREUSE=1`。
- 构建命令为 `dotnet build -c <Config> /m:1 /nodeReuse:false -v minimal`。
- 发布命令为 `dotnet publish -c Release -r win-x64 --self-contained true --output bin\Release\publish /p:PublishSingleFile=true /p:PublishTrimmed=true /m:1 /nodeReuse:false -v minimal`。

### 4.2 内存监控脚本 `scripts/内存优化.ps1`

```powershell
# 监控内存与 dotnet 进程
.\scripts\内存优化.ps1 -Monitor

# 清理构建缓存
.\scripts\内存优化.ps1 -Clean

# 终止高内存进程 (>2000MB)
.\scripts\内存优化.ps1 -Optimize
```

### 4.3 清理构建脚本 `scripts/清理构建.ps1`

释放磁盘空间与内存，依次执行：停止 dotnet 进程 → 删除 bin/obj → 清理 NuGet 缓存 → 清理 MSBuild/.NET 临时文件：

```powershell
.\scripts\清理构建.ps1
```

> 遇到内存警告或构建异常时，优先运行此脚本后重新构建。

## 5. 生产环境部署

### 5.1 发布应用

推荐发布自包含单文件版本（无需目标机安装 .NET Runtime）：

```bash
# 命令行发布
dotnet publish ComputerCompanion.csproj -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true /m:1 /p:UseSharedCompilation=false /p:ServerNodeReuse=false --output bin\Release\publish

# 或使用统一脚本
.\构建脚本.ps1 -Action Publish -Configuration Release
```

如目标机已安装 .NET 8.0 Desktop Runtime，可使用框架依赖模式（体积更小）：

```bash
dotnet publish ComputerCompanion.csproj -c Release -r win-x64
```

### 5.2 发布输出结构

```
bin/Release/publish/        # 自包含单文件
├── ComputerCompanion.exe   # 主程序可执行文件（单文件，包含运行时）
├── ComputerCompanion.pdb   # 调试符号（可选）
└── ComputerCompanion.dll   # 主程序集
```

> 框架依赖模式输出在 `bin/Release/net8.0-windows/win-x64/publish/`。

### 5.3 部署步骤

1. 创建部署目录：

```bash
mkdir "C:\Program Files\ComputerCompanion"
```

2. 将 `publish/` 下所有文件复制到部署目录。

3. （可选）创建快捷方式：右键 `ComputerCompanion.exe` → 创建快捷方式 → 移动到桌面或开始菜单。

### 5.4 管理员权限

- 硬件监控（CPU/GPU 温度、风扇等）需要管理员权限才能获取完整信息。
- 建议在 `ComputerCompanion.exe` 属性 → 兼容性 中勾选 "以管理员身份运行此程序"，或在应用设置内开启相关选项。
- 部署到 `C:\Program Files\` 目录本身也需要管理员权限写入。

### 5.5 开机自启配置

应用支持通过设置界面开启开机自启，会自动在以下注册表位置添加启动项：

```
HKEY_CURRENT_USER\SOFTWARE\Microsoft\Windows\CurrentVersion\Run\电脑伴侣
```

- 自启注册表写入 `HKEY_CURRENT_USER`，无需管理员权限。
- 若不生效，请以管理员身份运行一次程序以完成注册，并手动检查上述注册表项是否存在 `电脑伴侣` 键值且指向正确的 `ComputerCompanion.exe` 路径。

## 7. 运行时配置与故障排查

### 7.1 日志输出

应用通过 `Console.WriteLine` 与内置 `LogService` 输出日志（含敏感信息脱敏）。如需持久化，可重定向输出：

```bash
ComputerCompanion.exe > log.txt 2>&1
```

也可查看 Windows 事件查看器 → Windows 日志 → 应用程序，筛选来源 ".NET Runtime"。

### 7.2 杀毒软件误报

硬件监控（读取 CPU 温度、风扇转速等）行为可能被部分杀毒软件误报。处理建议：

- 将应用部署目录添加到杀毒软件白名单。
- 生产环境建议对 `ComputerCompanion.exe` 进行数字签名。
- 如误报持续，可向对应杀毒厂商提交误报申诉。

### 7.3 权限不足处理

| 现象 | 处理 |
|------|------|
| 提示"权限不足" | 右键 `ComputerCompanion.exe` → "以管理员身份运行" |
| 硬件信息显示为 `--` | 以管理员身份运行；检查显卡驱动；确认 LibreHardwareMonitorLib 已正确加载 |
| 开机自启不生效 | 以管理员身份运行一次；检查 `HKCU\...\Run` 下 `电脑伴侣` 键值路径是否正确 |

### 7.4 常见问题排查

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| 编译报 `CS0246 找不到类型` | 依赖未还原 | `dotnet restore` 后 `dotnet clean` 再构建 |
| 应用无法启动 | 缺少 .NET Runtime | 安装 .NET 8.0 Desktop Runtime，或使用自包含发布 |
| 悬浮窗不显示 | 被遮挡 / 多显示器 / 不支持透明 | 检查置顶设置、切换悬浮窗位置、确认显卡支持透明效果 |
| 网络速率显示负数 | 网络接口数据重置 | 已在代码中修复，更新到最新版本 |
| 构建占用大量内存 | 未启用单线程 / 节点重用 | 使用 `/m:1 /p:UseSharedCompilation=false /p:ServerNodeReuse=false`，运行 `scripts/清理构建.ps1` 后重建 |
| 触发内存警告 | GC 未限制 | 确认 `runtimeconfig.template.json` 中 `System.GC.HeapHardLimit=2147483648`（2GB）已生效 |

### 7.5 悬浮窗无法启动

1. 确认配置 `"EnableOverlay": true`。
2. 检查进程：`tasklist | findstr ComputerCompanion`。
3. 重启应用尝试重新启动悬浮窗进程。

## 8. 故障处理

### 8.1 应用崩溃

1. **查看事件查看器**：Windows 日志 → 应用程序，查找来源 ".NET Runtime" 的错误事件。
2. **检查日志**：应用目录与 Windows 事件日志中的详细错误信息。
3. **重建**：`scripts/清理构建.ps1` 后用单线程命令重新构建。

### 8.2 硬件监控失败

| 错误现象 | 处理步骤 |
|----------|----------|
| CPU 信息为空 | 确保 LibreHardwareMonitorLib 正确加载；以管理员身份运行 |
| GPU 信息为空 | 确认显卡驱动已正确安装 |
| 网络信息异常 | 检查网络适配器状态 |
| 电池信息异常 | 仅支持 Windows 平台 |

### 8.3 构建内存异常排查

```powershell
# 终止所有 dotnet 进程
Get-Process dotnet | Stop-Process -Force

# 清理缓存
.\scripts\清理构建.ps1

# 重新单线程构建
dotnet build ComputerCompanion.csproj /m:1 /p:UseSharedCompilation=false /p:ServerNodeReuse=false
```
